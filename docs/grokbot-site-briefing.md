# Site configuration brief for Grokbot: Walton-on-Thames.org

**Written:** 27 November 2026, for Darren to give to Grokbot alongside Search Console briefs. **Why this exists:** the 25 November brief (`docs/build-log.md`) was implemented with five departures, most of them caused by rules Grokbot could not see from the live site. This document describes those rules, so future recommendations fit the site the first time.

Everything below the line is the brief. Paste it to Grokbot as it stands. It describes the repository as of the date above; anything set in the Cloudflare dashboard is outside the repo and is marked as such.

---

## 1. What the site is

Walton-on-Thames.org is an independent community guide to Walton-on-Thames, Hersham and Whiteley Village in Surrey (Borough of Elmbridge). Canonical origin: `https://walton-on-thames.org` (apex, no www, HTTPS). Language `en-GB`, British spelling throughout.

## 2. Platform and hosting

- **Generator:** Astro 7, fully static (`output: 'static'`). Every page is pre-rendered at build time. There is no server-side rendering, no database and no CMS: content is Markdown with YAML frontmatter in a Git repository.
- **Host:** Cloudflare Pages. Every push to `main` rebuilds and deploys. A GitHub Action also triggers a rebuild daily at 01:00 UTC so that past events drop off listings and the Walton & Hersham FC fixtures feed is re-fetched.
- **URL format:** directory style with a trailing slash (`/things-to-do/riverside-walks/`). Treat the trailing-slash form as the canonical URL in any recommendation.
- **Edge cache (Cloudflare dashboard, not in the repo):** HTML can be cached at the edge for up to 7 days. A change can be deployed and correct yet not visible live for days until the cache is purged. When measuring "after deployment", count from the date Darren confirms the change is visible live, not the commit date.

## 3. Hosts and redirects

- **Canonical host enforcement:** a Cloudflare Pages Function (`functions/_middleware.js`) 301s every non-canonical host to `https://walton-on-thames.org`, preserving path and query. This covers `www.walton-on-thames.org` and `walton-on-thames.pages.dev`. Branch and deployment previews (`<name>.walton-on-thames.pages.dev`) keep serving, for review only.
- **Path redirects:** about 65 lines of 301 rules in `public/_redirects`, mostly GoDaddy-era and retired URLs (`/visit/*` to `/things-to-do/*`, `/eat-and-drink/*` to `/food-and-drink/*`, `/blog/*` and `/news/*` to `/community/news/*`, retired Hersham spokes to their merged pages). If Search Console shows a legacy URL, check whether it already redirects before proposing a new rule. Redirects must reach the final page in one hop.
- **hersham.org.uk:** a separate domain, redirected to the matching `/hersham/` pages by rules in the Cloudflare dashboard, not in the repo.

## 4. Crawling and indexing

- **robots.txt:** allows everything for every user agent and points to `https://walton-on-thames.org/sitemap-index.xml`. No AI crawler is blocked in the file. Cloudflare's dashboard bot settings (bot fight mode, AI crawler controls) are not visible from the repo; one known effect is that Cloudflare returns 403 to requests from GitHub-hosted runner IPs. If your fetches of the site fail with 403, say so rather than inferring the page is missing.
- **Sitemap:** generated by `@astrojs/sitemap` on every build, excluding `/contact/thank-you`. `lastmod` comes from a committed file built from full Git history, so it reflects when each page's source last changed, not the deploy time.
- **noindex:** set per page with a `noIndex` prop, which emits `<meta name="robots" content="noindex,nofollow">`. Currently noindexed: `/404`, `/search/`, `/contact/thank-you/`, `/privacy-policy/`, `/terms-and-conditions/`, `/accessibility-statement/` and `/walton-hersham-fc-away-fans-guide/` (noindexed automatically while its copy still contains placeholders; it becomes indexable once they are filled). Do not recommend optimising these for search.
- **Canonical tag:** every page emits `<link rel="canonical">` equal to its own clean URL unless a page sets one explicitly. Query-string variants (for example `/living/community/?area=hersham`) canonicalise to the bare path.
- **IndexNow:** every push to `main`, and daily at 01:10 UTC, a GitHub Action submits every sitemap URL to IndexNow (Bing, Yandex, Seznam, Naver, Yep). Google does not use IndexNow; Google discovery relies on the sitemap and Search Console.
- **Site search:** Pagefind, client-side, built from the deployed HTML. Indexable pages are searchable and noindexed pages are not. `/search/?q=` is the homepage's `SearchAction` target.

## 5. Titles and meta descriptions

- **Title suffix:** the layout appends ` | Walton-on-Thames.org` (23 characters) to a page title only if the title does not already contain "Walton-on-Thames" and the result still fits in 60 characters. Otherwise the title is emitted exactly as written. So a proposed title of 37 characters or fewer will gain the suffix, and one of 38 to 60 will not. Propose the full final title and its character count, and say whether you expect the suffix.
- **Meta descriptions:** target 140 to 160 characters on every indexable page. Listing and event pages (directory, what's on, places) top up a short description automatically with facts already on the page (address, date, venue), so a proposed base description for those only needs to stay under 160. Static pages and news articles must hit 140 to 160 as written. A build-time report lists any page outside the range.
- **History and Hersham articles** have a stricter schema: `metaTitle` at most 60 characters and `metaDescription` at most 155.
- **Open Graph and Twitter cards** mirror the final title and description; there is nothing separate to optimise.

## 6. Structured data in use

- **Homepage only:** `WebSite` (with `SearchAction`), `Organization` (logo, social `sameAs`) and `WebPage` whose `about` is a `Place` for Walton-on-Thames with Wikipedia and Wikidata (`Q2003600`) `sameAs`, geo and `containedInPlace` Surrey.
- **Across the site:** `BreadcrumbList` on most section and detail pages; `FAQPage` on a small number of pages (the homepage, `/hersham/`, Apps Court car boot sale and others); `Place`, `TouristAttraction`, `Park`, `SportsTeam`, `Event`, `Article`, `Person` and `ItemList` where the page content supports them.
- **`/hersham/`** carries a `Place` with `alternateName` "Hersham Village", geo, `containedInPlace` and `sameAs` to Wikipedia and Wikidata `Q5744439`.
- Every FAQ is visible on the page and the JSON-LD is generated from the same data, so a question cannot exist in the markup alone. Since August 2023 Google shows FAQ rich results only for government and health sites; the FAQs are kept for People Also Ask and AI answers, not expandable SERP results.

## 7. Site sections

- `/` homepage; `/hersham/` hub with spokes (history, food and drink, living, development and planning, Hersham Green and others)
- `/things-to-do/` with topic pages (families, free, rainy days, parks and walks, on the water) and individual attraction pages, including `/things-to-do/apps-court-car-boot-sale/`, whose open/closed status is updated automatically twice a day from the farm's own notice
- `/whats-on/` events (about 110 entries; past ones drop off at the daily rebuild)
- `/food-and-drink/`, `/shopping/`, `/places-to-stay/`, `/directory/` (about 180 business listings)
- `/living/` (areas, schools, GP surgeries, dentists, pharmacies, post offices, council and services, community clubs)
- `/history/` (about 36 articles), `/getting-here/` (plus parking and the two station pages), `/community/news/`, `/development-and-planning/`
- RSS at `/rss.xml`

## 8. Editorial rules your recommendations must respect

These are why proposals have been changed before. A recommendation that breaks one will be implemented with a departure or declined.

1. **No new facts from a brief.** Every proposed title, meta description, heading or FAQ answer must restate something already on the page and verified against an official source. If an answer needs a fact the page does not already state, flag it as needing research; do not supply the fact. Your own findings, and Grokipedia, are treated as leads, never sources.
2. **No em dashes anywhere.** The build fails on them. Use commas, colons or full stops.
3. **No opening hours, prices, fares, phone numbers or statistics from memory.** Quote them only if they already appear on the page. Phone numbers are written in the spaced form shown on the page (for example `01932 244 822`).
4. **FAQ limits.** `/hersham/` is capped at seven questions and is at the cap: propose a swap, not an addition. On any page, prefer one or two distinct questions over several near-duplicates, and do not repeat an answer already shown in a fact box directly above.
5. **Local government is changing.** Elmbridge Borough Council and Surrey County Council are replaced by East Surrey Council on 1 April 2027. Any wording about the council or borough must be dated accordingly, using the form already on the site.
6. **No new page where one exists.** The site keeps an audit of merged and retired pages. Prefer strengthening the existing page over a new URL; a proposal for a new page should say which existing page it would not cannibalise.
7. **Do not mirror a competitor's wording**, for example FAQ questions phrased as on appscourtfarm.com.

## 9. How to send a brief so it can be used

- State the Search Console date range and the property used.
- For each change: the page URL, the current value, the proposed value, the character count of the final rendered value, the query data behind it, and which sentence on the page supports any FAQ answer.
- Name cannibalisation pairs explicitly (for example "where is walton on thames" splitting between `/` and `/getting-here/`).
- For measurement, Darren sends you the date the change was confirmed live; return the same query tables for the 28 days after it.
